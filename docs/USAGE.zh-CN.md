# Go 跨平台打包使用说明

## 功能与入口

安装后打开一个 Go 项目，在 GoLand 右侧工具窗口栏点击 **Go 跨平台打包**。插件会扫描项目内声明 `package main` 的 `main.go`，按目录列出可构建入口。每个入口目录用 `go build` 构建，因此同目录中的其他 `.go` 文件也会一起参与编译。可以同时选择多个入口。

工具窗口顶部可以选择 Go 可执行文件。默认尝试使用当前项目在 GoLand 中配置的 Go SDK；若未找到，可手工指定 `go` 或 `go.exe`。点击 **重新扫描** 会再次扫描入口，并执行 `go tool dist list` 更新当前 Go 工具链支持的目标平台。

## 平台选择与排序

初次使用时，`linux/amd64`、`linux/arm64` 排在最前，其后依次是 `windows/amd64`、`darwin/arm64`、`windows/arm64`、`darwin/amd64`；其余平台按名称排列。勾选状态按项目保存，再次打开项目会恢复。

每次点击 **打包选中平台** 或 **全平台打包**，本次选中的每个平台各增加一次使用记录。即使同时选择多个 `main.go`，每个平台也只计一次。界面会显示“使用 N 次”，并立即按次数从高到低重新排列；次数相同时使用上述默认顺序。使用记录保存在当前项目的 IDE 工作区设置中，不会影响其他项目。失败或取消的打包也算一次选择，因为记录的是用户发起的选择，而非成功构建次数。

**全选平台** 只改变勾选状态，不增加使用次数；**清空平台** 会取消所有勾选。**全平台打包** 会全选并立即开始构建，因此会给列表中的每个平台各计一次。

## 输出目录

构建产物位于项目根目录的 `dist`，按入口和平台分目录保存：

```text
<项目>/dist/
  <入口名称>-<短标识>/
    linux_amd64/
      <入口名称>-<短标识>
      <入口名称>-<短标识>-linux-amd64.zip
    windows_amd64/
      <入口名称>-<短标识>.exe
      <入口名称>-<短标识>-windows-amd64.zip
```

短标识避免多个同名入口互相覆盖。Windows 目标生成 `.exe`，WebAssembly 目标生成 `.wasm`。每个 ZIP 内只有相应的构建文件。构建日志会逐个报告成功、失败和具体输出路径。

## 构建行为和限制

插件对每个目标设置 `GOOS`、`GOARCH` 和 `CGO_ENABLED=0`，在最近的 `go.mod` 所在目录执行构建。没有 `go.mod` 的入口按传统 GOPATH 模式构建。`dist`、`vendor`、`.git`、`.idea` 等目录不会被扫描。

“全平台”指当前 Go 工具链的 `go tool dist list` 所列平台。某些平台或项目依赖 CGO、额外系统工具或特殊构建标签，可能无法从当前系统完成交叉编译；失败原因会显示在日志中，其他目标会继续构建。

## 安装与升级

在 **Settings → Plugins → 齿轮图标 → Install Plugin from Disk** 中选择 `release/goland-cross-build-plugin-0.1.3.zip`，然后重启 GoLand。若右侧按钮被隐藏，可从 **View → Tool Windows → Go 跨平台打包** 打开。

已安装 `0.1.2` 时，可直接安装 `0.1.3` 更新。若仍安装 `1.0.1`，由于 `0.1.3` 的版本编号较低，先卸载 `1.0.1` 并重启 GoLand，再安装 `0.1.3`。插件 ID 和项目设置键保持不变，因此原来的平台勾选、Go 路径与使用次数可继续使用。后续版本使用 `0.1.4`、`0.1.5` 等编号。

图标沿用 Go Project Starter 的青蓝、白、黄色视觉语言：白色 G 代表 Go，黄色三向分支代表多平台输出。工具窗口使用 16×16 图标，插件列表使用 40×40 的明暗主题图标。Java 源码包名为 `com.github.yufuchang.crossbuild`。
